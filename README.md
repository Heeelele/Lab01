## 1. Лабораторийн зорилго

## 3. Орчин бэлтгэх

Playwright төслийг дараах командаар үүсгэж, шаардлагатай browser-уудыг суулгасан.

- `npm init playwright@latest my-first-test`
- `cd my-first-test`
- `npx playwright install`

## 5. Locator болон Assertion

Тест бичихдээ дараах locator-уудыг ашигласан.

- `getByRole()` — товч болон хэрэглэгчийн интерфэйсийн элемент олох.
- `getByPlaceholder()` — хэрэглэгчийн нэр, нууц үгийн талбар олох.
- `getByText()` — текстээр элемент олох.
- `locator()` — CSS selector ашиглан элемент олох.

XPath нь веб хуудасны HTML бүтэц өөрчлөгдөхөд эвдрэх магадлалтай байдаг. Иймээс илүү ойлгомжтой, тогтвортой тест бичихийн тулд Playwright-ийн орчин үеийн locator-уудыг ашигласан.

Тестийн үр дүнг дараах assertion-уудаар шалгасан.

- `toBeVisible()`
- `toHaveURL()`
- `toHaveText()`

## 6. Codegen ашигласан туршилт

Дараах командаар Codegen хэрэгслийг ажиллуулсан.

`npx playwright codegen https://www.saucedemo.com`

Codegen нь веб хуудас дээр хийсэн үйлдлүүдийг автоматаар TypeScript код болгон үүсгэж байсан. Үүсгэсэн кодод зарим давхардсан үйлдэл байсан бол өөрийн бичсэн кодыг туслах функц ашиглан илүү товч, ойлгомжтой болгосон. Мөн assertion нэмж тестийн үр дүнг баталгаажуулсан.

## 7. Trace Viewer болон санаатай алдааны туршилт

Тестүүдийг trace-тэй ажиллуулахдаа дараах командыг ашигласан.

`npx playwright test --trace on`

Барааг сагсанд нэмэх тестийн assertion дахь хүлээгдэж буй утгыг 1-ээс 5 болгон санаатай өөрчилсөн.

| Үзүүлэлт | Утга |
|---|---|
| Expected | 5 |
| Received | 1 |
| Timeout | 5000 ms |
| Үр дүн | FAILED |

Бодитоор сагсанд нэг бараа байсан тул тест амжилтгүй болсон. Алдааны мэдээллээр хүлээгдэж буй болон бодит утгын зөрүүг тодорхойлсон.

Дараа нь assertion-ийг зөв утгаар сэргээж, бүх тестийг дахин ажиллуулсан.

Trace Viewer нь тестийн үйлдлийн дараалал, веб хуудасны төлөв болон алдааны шалтгааныг судлах боломж олгодог.

## 8. Test Isolation болон Logout

Тестүүдийг бие даан ажиллах боломжтой байдлаар бичсэн.

Playwright нь тест бүрд тусдаа browser context ашигладаг тул нэг тестийн өгөгдөл нөгөө тестэд нөлөөлөхгүй.

Давхардсан кодыг багасгахын тулд `login()` болон `logout()` туслах функцүүдийг үүсгэсэн.

Амжилттай нэвтэрсэн тест бүр Logout үйлдлээр төгсдөг. Буруу нууц үгийн тест системд нэвтрээгүй тул Logout хийх шаардлагагүй.

## 10. Playwright болон Selenium-ийн харьцуулалт

1. Playwright нь веб автомат тест бичихэд ойлгомжтой API-тай санагдсан.
2. Playwright-ийн Auto-waiting боломж нь элемент бэлэн болохыг автоматаар хүлээдэг.
3. Selenium дээр зарим тохиолдолд explicit wait-ийг нэмэлтээр тохируулах шаардлагатай байдаг.
4. Playwright нь Chromium, Firefox болон WebKit browser-уудыг дэмждэг.
5. Codegen ашигласнаар тестийн эхний кодыг хурдан үүсгэх боломжтой.
6. Trace Viewer нь тестийн алдааг дэлгэрэнгүй судлахад тохиромжтой.
7. Playwright-ийн HTML Report нь тестийн үр дүнг ойлгомжтой харуулдаг.
8. Selenium нь олон программчлалын хэл болон browser-ийн өргөн экосистемтэй.
9. Энэхүү лабораторийн ажлаар Playwright ашиглан автомат тест бичих, ажиллуулах, алдааг шалгах боломжуудыг туршиж үзсэн.
